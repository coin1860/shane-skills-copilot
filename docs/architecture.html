🏛️ 架构核心理念 & 设计

Shane Skills 的设计目标是打破“单文件代码补全”的常规 AI 开发局限，引入系统化、方法论驱动的智能代理流程。 相比于传统的 Copilot 单句补全，Shane Skills 通过将开发者的每一步行动（思维风暴、技术选型、单元测试、调试排查）沉淀为独立的技能卡片（SKILL.md），并由插件将它们高效分发至开发者的工作区中，促成开发工具向方法论治理迈进。

系统架构中采用“主动集成（Active Integration）”与“被动集成（Passive Integration）”双轨运作方式：

⚡ 1. 主动集成 (Active @superpowers)

基于 VS Code 新版 chatParticipants API，注册专属的智能助手 @superpowers。 提供精确的 Slash 快捷指令（如 /tdd、/debug）。 插件在接收到指令后，在 Extension Host 进程中动态拦截并读取对应的技能定义，将技能方法论作为 System Prompt 强行组装进大模型请求，强力引导 Copilot 按照标准流程回复。

🧩 2. 被动集成 (Passive Discovery)

利用 GitHub Copilot 会自动检索并读取工作区中 .github/copilot-instructions.md 的特性。 插件激活时，会在本地工作区自动解压释出 .github/skills/ 下的 Markdown 技能定义，并在 copilot-instructions.md 中注入完整的技能索引表。 这使得当用户直接与默认的 Copilot Chat 闲聊沟通时，大模型能够基于索引自动引导用户使用 #file 读取所需的技能。

🚀 激活与工作区配置流程 (Workspace Setup Flow)

在插件激活或手动执行命令时，系统将内置包中的技能模板释放至工作区，为 Copilot 自动加载铺平道路：

1. Extension.ts 激活
插件启动，通过 WorkspaceSetup 组件校验工作区根目录是否已具备 Shane Skills 环境标签 (BOOTSTRAP_MARKER)。
2. 弹窗交互提示
若不存在或环境落后，询问用户是否为当前工作区部署 Shane Skills 方法论目录（含防重复打扰机制）。
3. 文件复制与生成
创建 .github/skills/ 并将 16 个核心技能 Markdown 文件释放入内； 生成 copilot-instructions.md 并自动收集所有技能的 Frontmatter 名字与描述写入技能字典。
4. 子代理模板选择
使用 VS Code QuickPick 气泡窗口向用户展示支持的 Agent 模板（SpecReviewer、Implementer 等），拷贝选中模板到 .github/agents/。
💬 @superpowers 命令执行流 (Participant Execution)

使用指令或 Slash 唤起时，插件在幕后完成 Prompt 组装与大模型调用桥接：

1. Slash Command 触发
用户输入诸如 @superpowers /tdd 写一个斐波那契函数。
2. 动态技能解析
Participant 拦截到命令：优先寻找本地工作区 .github/skills/test-driven-development/SKILL.md； 若无，则回退读取插件自身打包的内置技能内容。
3. 提示词融合与工具映射
融合技能原文，附带 Claude Code 工具映射指南（如 Read 映射为 #file、Bash 映射为终端等）， 将包装好的 System 级上下文合并用户输入组装为 LanguageModelChatMessage。
4. 调用语言模型
通过 VS Code 的 LanguageModelChat 发起真实的推理连接，读取返回流并通过流式渲染（ResponseStream）逐步绘制在 VS Code 聊天栏内。
📂 工程目录结构 (Project File Hierarchy)

本工程采用 TypeScript 开发，符合 VS Code 插件主流架构。主要文件布局如下： 

shane-skills-copilot/
├── src/
│   ├── extension.ts          # 插件主入口，负责生命周期和快捷菜单注册
│   ├── participant.ts        # @superpowers 拦截器、快捷命令处理与大模型对接
│   ├── skillRegistry.ts      # 技能文件缓存机制、Frontmatter 快速解析器
│   ├── workspaceSetup.ts     # 工作区一键初始化逻辑 (复制 md 及 agents 配置文件)
│   └── agentBrowserPanel.ts  # Webview 面板：查看与安装自定义子代理 (Agent) 
├── skills/                   # 内置 16 个核心技能库 (TDD, brainstorm, debug, 等)
│   ├── brainstorming/SKILL.md
│   ├── test-driven-development/SKILL.md
│   └── ...
├── templates/
│   └── agents/               # 子代理配置 (.agent.md 预置模板)
├── assets/                   # 图标、架构概念图等资源文件
├── package.json              # 插件清单，配置了 chatParticipants & commands 贡献点
└── tsconfig.json             # TypeScript 编译器配置
🔌 Extension Activator

src/extension.ts 是插件的心脏，负责协调各模块的生命周期。

  • 配置加载：读取用户配置，比如 superpowers.skillsSource (bundled 模式或外部 local 文件夹目录)。
  • 命令注册：如一键重载配置、打开 Skills Webview、Workspace 初始化配置等。
  • 状态栏提示：在 VS Code 右下角放置状态栏图标，实时反馈工作区是否部署了 Shane Skills。
📚 Skill Registry & Parser

src/skillRegistry.ts 实现轻量级的 Markdown 文本解析与磁盘缓存。

  • Frontmatter 解析：使用简单的正则表达式捕获 Markdown 顶部的 --- 块，解析出 YAML 级的 name 和 description。
  • 惰性加载与防抖机制：避免每次询问都遍历磁盘。仅在初次调用或执行 invalidate() (Reload Skills) 时，才会再次扫描文件。
  • 柔性匹配：支持按技能名称或文件夹目录名进行大小写无关的匹配。
🔨 Workspace Configurator

src/workspaceSetup.ts 帮助开发者跨越繁琐的配置阶段。

  • 动态文档生成：扫描源技能库，拼接出包含了每一项技能细节的字典表格，动态写入 copilot-instructions.md。
  • 多选多路部署：支持交互式 QuickPick，可选择性部署特定子代理的 .agent.md 到工作区的 .github/agents/ 中。
🖥️ Skills & Agents Webviews

src/agentBrowserPanel.ts 等提供了直观的用户交互视窗。

  • 可视化仪表盘：在独立的 VS Code 标签页中，渲染 HTML5 卡片墙，列出技能的徽章和作用。
  • 双向 IPC 通信：通过 postMessage 机制。当用户在卡片上点击时，向插件后台发送消息，拉起工作区中对应的 Markdown 文档供用户精读。
  • 安装检测：自动识别当前工作区缺失哪些 Agent，呈现出不一样的状态徽章 (✓ Installed / Template)。
🛡️ 工具映射与兼容性 (Tool Mapping Integration)

Shane Skills 原生的技能配置文件（如 SKILL.md）在编写时主要是面向 Claude Code 或具有强大终端工具执行能力的代理的。 然而，GitHub Copilot 本身的生态与 Claude Code 存在一定差异（Copilot 主要是基于编辑器环境的提问与补全）。为了让大模型在 Copilot 体系中发挥出同等实力，系统内置了智能工具映射系统 (Tool Mapping System)：

Claude Code 工具概念 VS Code / Copilot 映射逻辑 开发者具体操作
Read / 读文件 通过 Copilot 内部的 #file 或上下文绑定 在大模型需要读文件时，拖拽文件或在聊天栏直接输入 #文件名。
Write / Edit Copilot Chat 的行内编辑和编辑器修改机制 大模型生成代码片段后，开发者点击 "Insert" 或 "Apply to Editor"。
Bash / 运行命令 VS Code 终端面板 (Terminal) 引导大模型生成规范的命令行，开发者通过 VS Code 点击一键在终端执行。
TodoWrite / 状态追踪 本地的 task.md 任务清单 在大模型进行多步骤开发时，在根目录下维护一个 task.md 并在每次回复时更新其 [ ] 任务勾选状态。
Subagent / 子代理 工作区内 .github/agents/ 的自定义系统提示词 调用自定义 Agent 模板指令对大模型的系统角色重新设定。
✨ 系统技术亮点
  • 低内存足迹与无感加载： 整个插件基于静态配置拷贝与按需加载。在不使用 @superpowers 命令时，仅占据几十 KB 的运行时内存，没有任何额外的后台监听进程或网络中转开销。
  • 环境与插件分离： 一旦运行过 Setup Workspace，即使把此插件卸载，GitHub Copilot 也依然能凭借工作区中的 .github/skills/ 文件继续实现方法论开发。这保证了代码资产与环境的极佳移植性。
  • 完全的数据隐私安全： 所有的文件处理和拦截均在本地沙盒中完成，调用 Language Model 时使用的依旧是 VS Code 内部由微软和 GitHub 托管的安全信道，杜绝了代码及秘钥外泄的隐患。
  • 双通道缓存重载机制： 结合配置监听，在用户更改 localSkillsPath 时立即完成内存脏数据清理，支持开发时一键刷新，极为贴合技能开发者的调试需求。
